# 关于项目

## 项目目标

本项目用于实践从 Markdown 源文件到公开网站的完整发布流程。每次把指定文件推送到 `main` 分支后，GitHub Actions 会自动构建并部署网站。

## 技术组成

| 工具 | 在本项目中的作用 |
| --- | --- |
| Markdown | 编写结构清晰、便于版本管理的文档 |
| MkDocs Material | 把 Markdown 构建成带导航和主题的静态网站 |
| Git | 记录每次修改，便于查看历史和恢复版本 |
| GitHub Actions | 自动安装依赖、构建网站并执行部署 |
| GitHub Pages | 托管构建后的静态网页并提供公开地址 |

## 文件之间的关系

`docs/` 保存我编写的源文档，`mkdocs.yml` 保存网站配置。执行构建后产生的 `site/` 是构建产物，它可以随时由源码重新生成，因此不需要手工修改，也不提交到 `main` 分支。

## 为什么使用自动部署

自动部署把重复操作写进工作流。它能保证本地和云端使用相同的构建命令，并通过 Actions 日志留下可检查的过程。如果构建失败，可以根据红色步骤中的日志定位文档链接、YAML 缩进或依赖安装问题。
